Setup

  1. Install the bridge with one PowerShell command: powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/jlobue10/wireview-xeneon-edge/main/install.ps1 | iex". It downloads wireview-bridge.exe from the latest release, checks its SHA-256, and starts the bridge at logon. It serves JSON at http://localhost:8765/api/wireview and also serves these widgets locally.
  2. The bridge reads the WireView directly over its USB serial port (no HWiNFO needed). Close the Thermal Grizzly WireView app and disable its auto-start; only one program can hold the port.
  3. In iCUE, open the Xeneon Edge, add an iFrame widget, and paste one of the widget URLs above. Add ?wire_limit=10.5&total_limit=55 to match the limits set in the WireView device; the cable rating comes from the device itself.

Which URL? The bridge serves an identical copy of these pages at http://localhost:8765/…. Use that in the iFrame widget: page and data share one origin, so nothing can block the fetch. The hosted copy here is an https page reaching into localhost, which recent Chromium builds (Chrome 138+) treat as a Local Network Access request that needs a permission grant; a browser will ask, but an embedded webview may silently deny. iCUE 5.51 ships Chromium 130, which predates the rule, so the hosted URLs should work in its iFrame widget today; if one ever shows "Bridge offline" while the localhost one works, that is why.

Warning colour starts at 80 % of a limit, critical at 100 %; the device's own fault flags (over-current, over-power, over-temperature, imbalance) always show as critical with their name.
