# Rust audit — 2026-09-30

Audited baseline: `487babd9f9a47b6e2ac662d1dc6277c01d53747b`.
Scope: shared Rust readers/authentication, HTTP bridge and static assets, widget runtime,
installer and dependency tree. No critical or high severity issue was confirmed.

| Finding | Severity | Change |
| --- | --- | --- |
| WV-02: partial HWiNFO readings accepted as healthy | Medium | Require total amps, total watts, timestamp and all six pin currents, matching bridge JSON validation. |
| WV-03: stale readings stay healthy between long polls | Medium | Track receipt time with a monotonic clock and use an independent freshness watchdog, including response transit time. |
| WV-04: slow response readers restart the write timeout | Medium | Use an absolute connection deadline for every response write; send headers/body separately without copying the entire body. |
| WV-05: simultaneous secret creators return different keys | Medium | Lock before creation/repair and recheck the winner's contents; retain owner-only creation permissions on Unix. |
| WV-06: visibility changes create duplicate poll loops | Medium | Abort superseded requests and guard callbacks/timers by generation; register one visibility listener. |
| WV-07: local widgets ignore custom bridge ports | Medium | Use the local page's origin unless `host` is explicitly provided; hosted pages retain the default loopback origin. |
| WV-08: copied installer leaves installed executable behind | Low | Record managed download ownership, recognise older default installs and explicit custom directories, remove only installer-owned files. |

Regressions cover incomplete/non-finite HWiNFO fields, simultaneous creators (including
short-file repair), slow socket readers, long intervals, stale/late replies, visibility
restarts, IPv4/IPv6 custom ports and installer ownership/user-file preservation.
The new widget and installer checks run in CI alongside Rust tests on Linux and Windows.

Local verification: 67 Rust tests, eight JavaScript tests, installer checks, formatting,
Clippy with warnings denied, and cargo-audit passed. The updated lockfile has 72 packages;
RustSec reported no known vulnerabilities or maintenance warnings on this audit date.

The companion [Nexus audit branch](https://github.com/jlobue10/wireview-nexus/tree/audit/rust-hardening-2026-09-30)
updates its lockfile for these shared-core changes and fixes its renderer, HID backend and
font parser. Merge this shared-core change before the companion Nexus change: Nexus CI
uses matching branch names, then falls back to this repository's main branch.

Hardware validation still needed: real HWiNFO shared memory, serial disconnect/reconnect,
iCUE/Xeneon stale overlays and custom ports. Unit tests use fixtures; installer tests mock
administrative APIs and do not verify actual Scheduled Task registration.
